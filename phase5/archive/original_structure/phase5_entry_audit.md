## C. What is missing

1. **Tier-A human gold: 0 labels.** No raw forms, no adjudication, no freeze files.
2. **District 30 m cube: not built.** Only the 3 windows (5.8 %) have 30 m data.
3. **Gold-file freeze and refusal code.** `docs/phase4_gold_protocol.md` §4 says "the evaluation code refuses unfrozen files". No such code exists; it is built in Phase 5 (`src/validation/`).
4. **Gold ingestion and validation pipeline.** None exists; only agreement statistics do.
5. **Human training labels for P4-C1@v2 arms C, D and E.** Arms C (independently validated silver), D (human gold-training) and E (gold + filtered silver) need human labels *outside* the validation blocks. The protocol forbids training on validation-block gold. No training-sample design, form or kit exists.
   * This is a **specification gap in a pre-registered experiment**, found before any data exist. It is handled as a dated addendum (§H, `docs/phase5_execution_plan.md`), not as a protocol change.
6. **Sentinel-1/2 on the district grid.** Needed by P4-C6@v2.
7. **Products not yet compared.**
   * Dynamic World and GAIA need Earth Engine.
   * JRC is used for strata and PIFs but not benchmarked.
   * ALOS FNF and MS building footprints are acquirable but not acquired.
8. **Non-imagery data.** No taluka boundaries, census, gauge, reservoir-storage or crop-statistics data exist (W17, W18).

Two inputs only a human or an outside resource can supply:

1. **Human interpretation.** Gold, and the training sample T1.
2. **Compute for the full cube.** Either a VM running the existing Planetary Computer engine, or an Earth Engine project for the GEE script.

Everything else on the path is code, already testable.
